# 商业精英流通业竞赛教练

`coach-cubec-circulation` 是面向“全国高校商业精英挑战赛创新创业竞赛——流通业经营模拟赛道”的 Codex Skill。它将备赛工作组织为有阶段门、可追溯证据和确定性校验的完整流程：

> 项目简报 → 选题 → 调研 → 分析报告 → 评分复核 → 20页PPT大纲 → 10分钟讲稿

5分钟答辩题库和最终合规预检为可选延伸。

## 1. 项目解决什么问题

本项目解决流通业经营模拟赛道备赛中常见的六类问题：

1. **流程割裂**：选题、调研、报告、评分、PPT和讲稿往往分别完成，前后结论和数据容易不一致。本 Skill 使用阶段门和版本锁定让后一阶段只能建立在已确认的前一阶段之上。
2. **选题不合规或无法调研**：帮助筛选真实的批发、零售、餐饮、物流等流通企业，检查企业在院校所在省的经营布局、典型性、地区问题和取证可达性。
3. **同校企业重复风险**：使用内置2025名单进行初筛，并明确区分 `BLOCK`、`REVIEW`、`CLEAR_IN_FILE` 与校级人工确认后的 `CONFIRMED_CLEAR`。
4. **报告缺少证据闭环**：把调研材料组织为证据台账，形成“症状—差距—根因—方案—KPI”的经营分析闭环，避免先定结论再拼数据。
5. **评分和展示脱离正文**：依据官方60分五维标准进行证据定位式复核；PPT和讲稿必须映射到锁定报告，不允许新增无来源数字、访谈或方案收益。
6. **AI幻觉与合规风险**：禁止虚构问卷、访谈、观察、财务、政策、企业动作和收益；缺失内容必须标记为 `[待调研]`、`[待核验]` 或 `[团队判断]`。

本 Skill 是备赛辅导与质量控制工具，不替代团队的真实调研、事实核验、实质性写作和现场彩排，也不保证获奖、晋级、原创认定或查重通过。

## 2. 主要功能

### 2.1 项目建档与阶段管理

- 记录竞赛年份、组别、地区、截止时间、候选企业、已有证据和目标交付物。
- 识别用户当前所处阶段，只继续当前任务，不重复已完成工作。
- 使用阶段门控制报告、PPT和讲稿的生成顺序。

### 2.2 企业选题与查重初筛

- 按省份、可调研城市和业态生成8—12家候选企业池。
- 核验流通业属性、本省实际布局、公开资料和一手调研可达性。
- 为前三名候选企业形成可证伪的问题方向和中心命题。
- 使用内置名单检查同校企业和相似标题风险：

```bash
python3 scripts/check_case_duplicate.py \
  --school "学校官方全称" \
  --enterprise "企业全称|品牌名|常用简称" \
  --title "拟定作品标题"
```

该脚本仅基于项目内置的2025名单进行筛查，不能替代最新官方名单、本校登记记录和校级负责人的最终确认。

### 2.3 调研设计与证据管理

- 将中心命题拆解为研究目标、研究问题和可证伪假设。
- 提供研究计划、参与者筛选、问卷、访谈、门店观察、竞品对标、数据清洗及证据台账模板。
- 要求核心瓶颈至少获得两类独立证据支持，其中至少一类为目标地区的一手证据。
- 明确记录样本口径、反证、替代解释、研究限制和人工核验状态。

### 2.4 分析报告框架与分章节写作

- 从往届11份国一作品中蒸馏章节功能与论证经验，但不复制原文、数据、图表、视觉或结构性创意。
- “分析报告框架确认单”固定为 11 章三级施工框架：目录、概要、引言、案例简介、企业内部分析、企业外部分析、企业经营模式、发展瓶颈、经营优化方案、结论与启示、附录及参考资料。
- 概要采用两个二级标题“研究对象与核心问题、主要结论与方案方向”；引言采用正式标题“研究背景与选题价值、研究设计与范围”；案例简介保持凝练。企业内部分析只保留企业战略、运营管理、财务状况三个二级标题，并删除6.4与7.4。
- 每个三级标题下必须有2—3行结合项目材料的概括。第8章保留2—4项瓶颈，二级标题直接概括“问题+后果”；第9章设置同等数量的对应方案，二级标题直接概括“改善结果+核心做法”。
- 第11章固定包括：企业重要数据概览、调查问卷、访谈纲要（含知情说明与编码）、参考文献、观察/竞品与现场记录、补充图表与地区对标。
- 先输出框架，待结构校验通过且用户明确确认后再分章节写作。
- 正文固定分为三批：B01“引言+案例简介”→用户确认；B02“企业内部分析+企业外部分析+企业经营模式”→用户确认；B03“发展瓶颈+经营优化方案+结论与启示+附录及参考资料”→用户确认。三批全部接受后才写概要、目录并组装全文。
- 第4—7章的重要主张必须援引可打开并精确定位的专业文献、公开权威机构报告/数据、权威网站、企业官方披露或项目一手证据，并按章节需要开展同口径竞品分析、消费者洞察、产品分析和财务分析；不能访问原文时不得伪造引用。
- 每个企业事实或判断标记为 `[已核验:E###]`、`[待核验]`、`[待调研]`、`[待验证假设]` 或 `[团队判断]`；`[已核验:E###]` 必须绑定同一证据 ID 和精确定位。
- 将每项方案绑定根因、责任主体、实施阶段、资源、KPI、风险、触发条件和回滚措施。
- 量化分析先调用数据验证 Skill，再由数据可视化 Skill 选择图形、生成静态图并做轴线/口径/可读性检查。
- Word 使用文档 Skill 制作 A4 竖版 DOCX、页眉页脚、图题表题、交叉引用与隐私清理；Kami 1.12.0 已嵌入 `integrations/kami/`，提供视觉和图解参考。Kami 原生输出 HTML/PDF，不被描述为 Word 生成器。
- 最终 DOCX 必须渲染为逐页 PNG 人工检查；每个渲染页至少有一张与主张相关且有来源的图片，或一张真正用于比较/查阅的表格，不能用装饰图或“段落套表格”凑数。

```bash
python3 scripts/validate_report_framework.py path/to/report-framework-approval.md
python3 scripts/validate_word_visual_manifest.py path/to/word-visual-manifest.json
```

框架脚本可拦截固定11章或精简二三级标题缺失、五个核心经营维度错位、已删除章节重新出现、第11章六项附录缺失、三级概括不足、瓶颈/方案不在2—4项或数量不一致、抽象二级标题、主张无状态，以及“已核验”但没有证据定位等错误。Word清单脚本检查最终页码连续、每页图/表与主张/来源映射、页眉页脚、匿名和重排后复核声明；二者都不能代替人工核验来源真实性或逐页视觉检查。

### 2.5 官方60分评分复核

- 按分析框架20分、分析对象10分、分析视角10分、分析方法10分、分析结论10分复核。
- 为每个评分项提供报告定位、证据状态、支持与反证、分数区间和置信度。
- 报告不完整、不可读或只有提纲时标记为 `UNSCORABLE`，不强行给出60分数字。
- 国一经验只用于定性成熟度诊断，不作为额外加分项。

### 2.6 恰好20页PPT大纲与可选HTML演示

- 只根据已确认的完整报告生成恰好20页初版大纲。
- 每页包含结论式标题、页面任务、主张与证据、报告定位、建议视觉、口播任务和时间预算。
- 大纲获得用户确认并通过校验后，可调用独立的 `$frontend-slides` Skill 制作1920×1080单文件HTML演示。
- `frontend-slides` 不原生生成可编辑PPTX；如需PPTX，需要另用演示文稿工具重建。

```bash
python3 scripts/validate_ppt_outline.py path/to/ppt-outline.json
python3 scripts/validate_ppt_outline.py --for-production path/to/ppt-outline.json
```

### 2.7 10分钟逐页讲稿与彩排校验

- 基于锁定的报告和已确认20页PPT生成 `[P01]` 至 `[P20]` 逐页稿与连续讲稿。
- 记录讲述人、每页秒数、来源、舞台动作、过渡句和应急删减句。
- 默认口播预算554秒，预留46秒现场缓冲。
- 最终通过需要使用团队实测速率，并满足最后三轮彩排均不超过600秒、中位数为525—570秒。

```bash
python3 scripts/validate_ten_minute_script.py path/to/script.json
python3 scripts/validate_ten_minute_script.py --for-final path/to/script.json
```

### 2.8 答辩与最终预检

- 可生成不少于40题的5分钟答辩题库，覆盖地区性、样本、方法、经营维度、根因、成本、风险和AI使用边界。
- 检查匿名、最低报告模块、地区性、来源标记、同校查重状态和人工确认状态。

```bash
python3 scripts/validate_project.py \
  path/to/report.md \
  --meta path/to/project-meta.json
```

项目预检脚本目前只直接读取 Markdown 或 TXT 报告。PDF、DOCX需先通过相应文档工具完整读取和视觉检查；自动脚本不能证明事实真实、问卷有效或原创合规。

## 3. 安装方法

### 3.1 当前电脑

本 Skill 已安装在：

```text
~/.codex/skills/coach-cubec-circulation
```

当前电脑无需再次安装。重新打开一个 Codex 任务后，即可通过 `$coach-cubec-circulation` 调用。

### 3.2 安装到其他 Codex 环境

1. 复制**整个** `coach-cubec-circulation` 文件夹，不要只复制 `SKILL.md`。
2. 将文件夹放入 Codex 的 Skills 目录：

```text
~/.codex/skills/coach-cubec-circulation/
```

3. 确认以下文件存在：

```text
coach-cubec-circulation/
├── SKILL.md
├── README.md
├── agents/openai.yaml
├── assets/
├── integrations/kami/
├── references/
└── scripts/
```

4. 重新打开 Codex 任务或刷新技能列表，确认可以看到“商业精英流通业竞赛教练”。

基础结构校验不需要安装Python第三方包，只需要Python 3。制作Word、静态图表和逐页渲染时，应在运行环境中提供 `$documents:documents`、`$data-analytics:validate-data` 和 `$data-analytics:visualize-data`；若这些能力不可用，必须改用可复现的本地数据/文档工具并如实说明未完成的门禁。Kami 已随本项目嵌入，无需另行下载。制作单文件HTML演示仍需要单独安装 `$frontend-slides` Skill。

本机维护版本另有被 `.gitignore` 排除的 `source-materials/` 和 `source-skills/` 只读原始档案；其中含赛事附件、往届作品和旧 Skill 快照，因版权与隐私边界不随公开 GitHub 仓库分发。仅在得到合法来源与使用权限时，才可把对应原件放回这两个目录；公开版本的主流程、模板、蒸馏规则和校验脚本不依赖这些原件运行。

## 4. 使用方法

### 4.1 推荐调用方式

在 Codex 对话中明确调用 Skill，并说明当前阶段：

```text
使用 $coach-cubec-circulation。
我是江苏省本科组，目前处于选题阶段。学校官方全称是……，
可以实地调研南京市，偏好零售或物流企业，请从项目简报开始。
```

如果已经有成果，应直接上传或给出文件路径并说明版本：

```text
使用 $coach-cubec-circulation。
这是已经确认的调研资料和报告框架，请从报告分章节写作继续，
不要重做选题。报告框架版本为 V1.2。
```

### 4.2 各阶段建议输入

| 阶段 | 建议提供的输入 | 本轮主要输出 |
|---|---|---|
| 项目简报 | 年份、组别、截止时间、省份、城市、已有材料 | 项目状态、缺口、下一步 |
| 选题 | 学校全称、省份、可调研城市、偏好业态、可接触资源 | 候选池、查重初筛、前三名、中心命题 |
| 调研 | 已确认企业、中心命题、可接触对象、时间与人员 | 调研计划、工具、证据台账、补证清单 |
| 报告框架 | 已确认选题、调研材料、证据台账、引用来源 | 固定11章三级“分析报告框架确认单”、五维固定落点、2—4项瓶颈、主张—证据登记 |
| 报告正文B01 | 已确认框架、引言/案例简介证据包 | 第3—4章、主张—证据定位、缺口、待确认版本 |
| 报告正文B02 | `B01_ACCEPTED`、第5—7章权威证据与分析资料 | 第5—7章、竞品/消费者/产品/财务分析、图表契约、待确认版本 |
| 报告正文B03 | `B02_ACCEPTED`、瓶颈—方案证据链 | 第8—11章、方案KPI/风险/回滚、待确认版本 |
| Word/PDF | `B01/B02/B03_ACCEPTED`、已核验图表数据 | 概要、目录、A4 DOCX/PDF、逐页图/表覆盖清单与视觉复核结果 |
| 评分 | 唯一完整报告版本及附件 | 可评分性、60分工作分/区间、证据定位、整改项 |
| PPT | 已确认完整报告及其版本 | 恰好20页初版大纲、来源映射、待确认项 |
| 讲稿 | 已确认20页PPT、锁定报告、讲述人数与实测速率 | 20页逐页稿、连续稿、时间与彩排记录 |

### 4.3 使用原则

- 后一阶段的输入未锁定时，Skill 会停在当前阶段，不提前编造下一阶段成品。
- 学校名称只用于内部项目简报和查重，不得进入匿名报告、PPT、讲稿或视频正文。
- 用户上传更新版细则时，以新细则为准；2026细则只作为当前内置基线。
- 原始国一作品用于方法蒸馏和质量对照，不用于改写或仿制。
- 报告固定章节、通用三级施工功能和五个核心经营维度主落点不能由案例偏好覆盖；用户可根据证据调整第8、9章的二级结果标题、2—3行概括、篇幅和重点。
- 分章顺序固定为B01→B02→B03；每批交付后等待用户确认。概要和目录最后生成，不能用未证明结论预填。
- 每一张图表都要绑定主张、数据、来源和口径；Word是否满足“每页有图或表”只按最终渲染页判断，重新分页后必须重新检查。
- 每轮输出末尾都会说明当前阶段、已确认事实、待核验事项、团队必须亲自完成的工作和下一步。

## 5. 输入输出示例

以下示例展示交互形式，不包含可提交的竞赛内容或虚构调研数据。

### 示例一：信息不足时启动选题

**输入**

```text

我是江苏本科组，只确定了省份，还没有企业、学校全称和调研材料，
但最终需要20页PPT大纲和10分钟讲稿。请直接开始。
```

**输出摘要**

```text
当前阶段：阶段0“项目简报与规则锁定”
阶段门状态：待核实
案例企业：[待选择]

筛选依据、前三名方向和查重状态。
```

### 示例二：由调研成果生成报告框架确认单

**输入**

```text
使用 $coach-cubec-circulation。
选题和调研已完成。这是证据台账、访谈整理、问卷与公开来源，
请先生成分析报告框架确认单；没有来源的内容不要补写。
```

**输出结构**

```text
状态：FRAMEWORK_DRAFT
不支持主张：0

1. 目录
2. 概要
3. 引言
4. 案例简介
5. 企业内部分析
   5.1 企业战略
   5.2 运营管理
   5.3 财务状况
6. 企业外部分析
   6.3 市场竞争
7. 企业经营模式
   7.1 商业模式
8. 发展瓶颈（2—4个二级标题直接写“问题+后果”）
9. 经营优化方案（与瓶颈一一对应，二级标题写“改善结果+做法”）
10. 结论与启示

   11.2 调查问卷
   11.3 访谈纲要（含知情说明与编码）
```

如果证据不足，框架只保留问题、取证任务或待验证假设，不会生成企业事实。用户确认某一框架版本后，才进入分章节正文写作。

### 示例三：按三批写作并生成逐页有图表的Word

**输入**

```text
使用 $coach-cubec-circulation。
框架V1.2已经确认，请先写引言和案例简介。第4—7章必须使用可核验的
专业文献、公开权威资料和企业披露；每一批都等我确认。全部确认后生成
A4 Word，页眉页脚规范，最终每页至少有一张图片或一张真正的表格。
```

**输出顺序**

```text
B01-v0.1：第3—4章 + 来源定位 + 图表计划 → AWAITING_USER_APPROVAL
用户确认B01
B02-v0.1：第5—7章 + 竞品/消费者/产品/财务分析 + 数据验证 → AWAITING_USER_APPROVAL
用户确认B02
B03-v0.1：第8—11章 + 瓶颈—方案—KPI闭环 → AWAITING_USER_APPROVAL
用户确认B03
概要与目录 → A4 DOCX/PDF → 逐页PNG复核 → word-visual-manifest PASS
```

若某一来源无法打开、财务口径不一致或任一渲染页没有合格图/表，输出会保留缺口并停在对应阶段，不会用虚构引用、装饰图片或段落套表格补齐。

### 示例四：上传完整报告进行评分复核

**输入**

```text
使用 $coach-cubec-circulation。
请复核我上传的完整报告 V2.1。按照官方60分标准评分，
每一项都给出报告页码或章节定位；无法核验的内容不要推测。
```

**输出结构**

```text
版本锁定：报告 V2.1
可评分性：SCORABLE / PROVISIONAL / UNSCORABLE
证据级别：REPORT_ONLY / PARTIALLY_VERIFIED / EVIDENCE_VERIFIED

1. 分析框架（20分）：工作分、合理区间、置信度、报告定位
2. 分析对象（10分）：工作分、合理区间、置信度、报告定位
3. 分析视角（10分）：工作分、合理区间、置信度、报告定位
4. 分析方法（10分）：工作分、合理区间、置信度、报告定位
5. 分析结论（10分）：工作分、合理区间、置信度、报告定位
```

如果上传内容只有提纲、截图或不可读文件，输出会标记为 `UNSCORABLE`，不会生成虚假的60分结果。

### 示例五：从锁定报告生成PPT与讲稿

**输入**

```text
使用 $coach-cubec-circulation。
报告 V3.0 已经确认，请先生成20页PPT初版大纲。
每页必须标注报告来源；我确认大纲后，再继续制作演示和10分钟讲稿。
```

**第一轮输出**

```text
状态：PPT_OUTLINE_DRAFT
来源报告：V3.0
页数：20

P01—P20：每页给出结论式标题、页面任务、核心主张、证据ID/报告定位、
建议视觉、口播任务和秒数。

同时输出：报告主张—PPT页映射、待补证项、需要用户确认的版本号。
```

用户确认大纲后，才进入HTML演示制作；PPT与报告再次锁定后，才生成20页逐页讲稿和连续逐字稿。讲稿只有经过真人语速测量及三轮彩排，才能标记为最终通过。
