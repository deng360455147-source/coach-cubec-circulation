# 流通业经营研究半结构化访谈纲要

> 本模板蒸馏了往届优秀作品常见的多角色访谈结构，并补入专业咨询研究的知情、追问、反证和编码要求。它是母版，不是同一套问题同时问所有人；必须按角色删改。不得虚构受访者、原话、样本量或访谈结果。

## 1. 访谈前筛选与知情说明

### 1.1 筛选

核对角色、所在地区、接触企业/业务的时间和最近一次相关经历。不得因受访者“职位高”就默认其了解所有经营环节，也不得把顾客意见当作内部运营事实。

### 1.2 口头知情说明

“您好，我们正在开展【研究主题】。本次交流预计约【】分钟，目的是了解您最近的真实经历和经营观察，没有标准答案。参与完全自愿，您可以跳过任何问题或随时结束。我们会用匿名编号整理材料，只在本次研究允许的范围内使用；不会在报告中披露能够识别您个人的信息。是否同意继续？是否同意录音？是否同意使用您主动提供并经确认的材料？”

分别记录“参与、录音、拍照/材料使用”三项同意；任何一项不同意都不能擅自执行。不要承诺绝对保密、永久删除或其他团队无法保证的事项。

## 2. 所有角色的共同主线

1. 请介绍您与【具体业务/场景】的关系，以及最近一次接触发生在何时、何地。
2. 请从头讲述最近一次具体经历：触发了什么需求，经过哪些环节，谁参与，最终结果如何？
3. 哪一步最顺利，哪一步最困难？请给出当时可观察的例子、时间、数量或处理动作。
4. 当时有哪些替代方案？为什么选择或放弃？
5. 这个现象多久发生一次，在什么条件下不会发生？
6. 它对收入、成本、效率、库存、时效、服务或风险产生了什么可观察影响？哪些只是您的判断？
7. 有没有与我们当前假设相反的经历或更合理的解释？
8. 若要验证您的判断，最需要查看哪项记录、数据或另一类受访者？

通用追问：`请讲最近一次`、`当时具体发生了什么`、`您如何知道`、`能否给一个反例`、`这一点可以由什么记录核对`。不争辩、不推销方案、不用“是不是因为……”诱导答案。

## 3. 管理层/企业负责人模块

1. 当前阶段最重要的经营目标、约束和取舍是什么？该判断可由哪些公开或内部指标支持？
2. 企业战略如何落到地区、业态、门店/网点、品类、渠道和客户选择？近年发生过哪些可核验调整？
3. 主要收入、成本、资源投入和风险来源是什么？哪些信息可以公开，哪些只能作为背景理解？
4. 关键决策由谁提出、审批和执行？跨部门协同最容易在哪个节点失效？
5. 对主要竞品和地区差异的判断依据是什么？有没有与市场表现不一致的内部预期？
6. 当前已尝试哪些改善动作？起止时间、覆盖范围、基线、结果和失败经验分别是什么？

不得要求或记录与研究无关的商业秘密、个人信息或未授权数据；未取得原始记录时，管理者口述不能直接写成已实现业绩。

## 4. 门店/网点负责人模块

1. 一天/一周中的高峰、低峰和异常时段如何变化？排班、库存、设备和服务如何匹配？
2. 从到货/接单到交付/售后，哪些节点最常出现等待、缺货、返工、损耗或投诉？
3. 指标如何记录、复盘和上报？哪些指标容易被遗漏或被平均值掩盖？
4. 总部规则与本地商圈、交通、气候、节庆、竞争或消费习惯在哪些方面不匹配？
5. 遇到异常时谁有权限处理，响应需要多久，最常见的权宜做法是什么？
6. 最近一次成功或失败的改进是什么？其前后口径和外部干扰能否核对？

## 5. 一线员工模块

1. 请按实际操作演示或描述最近一次完整服务/作业流程。
2. 哪些步骤最耗时、最容易重复录入、等待、出错或需要经验判断？
3. 绩效目标、培训、系统、设备和排班如何影响实际行为？是否存在目标冲突？
4. 顾客/商户最常提出什么问题？员工通常如何处理，哪些问题无法在一线解决？
5. 如果只能改一个流程节点，您会改什么？为什么？需要什么资源和权限？

不得询问个人绩效、劳动争议或敏感身份，除非研究伦理、匿名和必要性已充分处理。

## 6. 供应商/加盟商/合作方模块

1. 合作开始、日常协同、结算、补货/履约和异常处理的真实流程是什么？
2. 订单、预测、库存、质量、价格或信息共享中最常见的偏差是什么？
3. 合同规则与实际执行在哪些场景不一致？造成了什么可观察影响？
4. 与其他渠道或企业合作相比，案例企业的优势、成本和风险分别是什么？比较是否同地区、同品类、同期？
5. 哪些改进会真正改变合作行为？需要何种保障、数据或试点结果？

## 7. 消费者/用户模块

1. 最近一次需求是如何产生的？为什么在当时、当地选择该企业或渠道？
2. 从搜索、比较、下单/进店、支付、交付到售后，最关键的触点是什么？
3. 价格、品类、质量、便利、时效、服务和信任中，哪一项真正改变了最后选择？请举例。
4. 是否遇到缺货、等待、信息不一致、退款或投诉？当时采取了什么行动？
5. 实际使用过哪些同地区竞品？在完全相同的场景下有什么差异？
6. 什么情况下会再次选择、换渠道或不再购买？需要看到什么真实改善？

## 8. 方案反应模块（完成问题探索后再问）

先展示统一、无夸张承诺的方案卡，再问：

1. 您如何理解这个方案，它解决的是哪个具体问题？
2. 哪些场景有效，哪些场景无效或会产生副作用？
3. 最大执行成本、依赖、风险和阻力是什么？
4. 谁应负责，先在哪个小范围试点，什么指标达到才推广？
5. 出现什么信号应暂停、调整或回滚？

方案反馈只代表受访者判断，不能写成方案已经实施或取得成效。

## 9. 收尾

1. 有没有重要内容尚未覆盖？
2. 有没有材料可以在授权范围内核对上述判断？
3. 还有哪些角色可能提供相反证据？
4. 再次确认资料使用边界，并说明后续不会默认联系或公开身份。

### 编码流程

1. 逐字稿或结构化记录与研究者备忘分开保存；先匿名化，再进入分析。
2. 先开放编码少量样本，形成代码本；再由至少两名团队成员复核关键主题和分歧。
3. 保留支持证据、反证、角色差异、地区差异和时间条件；不只统计高频词。
4. 主题频次只表示本访谈样本中的出现情况，不能当作总体比例；词云只有在合格文本量和清洗条件满足时才使用，并与词频表/主题表成对。
5. 记录原始记录、编码版本、合并/拆分原因和引用位置，确保从报告判断回溯到匿名记录。

## 12. 附录交付清单

附录应包含：按角色分组的正式访谈纲要、知情说明、招募和筛选条件、匿名编号规则、访谈执行说明、主题代码本及必要的样本结构。原始录音、可识别逐字稿和联系方式不进入公开作品。若访谈尚未真实执行，只能标为“拟用访谈纲要”，不得生成匿名编号、原话或结论。
