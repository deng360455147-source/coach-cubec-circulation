# 合规与最终交付

## 状态口径

只使用：

- `PASS`：存在可定位证据；
- `RISK`：已发现违反、冲突或高概率失分；
- `NOT_VERIFIED`：缺信息，不能默认通过；
- `BLOCK`：命中明确资格或原创红线，停止提交。

## 硬性与资格检查

- 规则年份、组别、团队人数、跨校/跨队限制已核实；
- 企业属于批发、零售、餐饮、物流等流通行业且较典型；
- 企业在院校所在省有可核验经营布局；
- 同校2025–2026案例企业查重达到 `CONFIRMED_CLEAR`；
- 报告包含官方最低八模块，并覆盖战略、商业模式、运营、市场竞争和财务/经营代理指标；
- 报告为A4竖版PDF且不少于3000字；PPT不少于20页，本skill初版为恰好20页；
- 封面只含团队名、作品名、案例企业名；报告、PPT、视频、讲稿、图表、附件和文档属性无院校、姓名、联系方式或校徽；
- 提交文件名按 `学校名称-团队名称-作品名称`，不要把文件名含学校与作品内部匿名误判为冲突；
- 引用、图片、Logo、字体和企业素材有合法使用依据；
- 无抄袭、无完全AI撰写，团队保留调研底稿、版本历史、人工修改和贡献记录。

## 证据与结论检查

- 每个实质数字能定位到来源或计算；时间、地区、单位和业务口径一致；
- 集团/全国数据未冒充目标地区或门店数据；
- 问卷记录总体、渠道、期间、有效样本、清洗和偏差；访谈/观察由团队真实完成并脱敏；
- 一手证据与公开证据交叉验证，反证与冲突未被隐藏；
- 相关关系未越界写成因果，非上市企业财务未被虚构；
- 方案收益清楚区分事实、假设和保守/基准/乐观情景；
- 团队能口头解释中心问题、核心数字、方法、根因、方案和AI辅助边界。

## 文件与现场检查

1. 锁定唯一报告、PPT、讲稿和视频版本，记录哈希/版本号。
2. 检查PDF页序、自动目录是否覆盖全文一级/二级/三级标题、字体、图表来源、附件隐私和可搜索性；核对正文小四宋体/英文数字Times New Roman、1.25倍行距、页边距、只在一级标题前分页、图前正文、图内无题注且文字12pt、表格单元格居中且零首行缩进，以及图下表上9pt小五黑体居中题注与真实自动编号域。
3. 检查20页PPT的页数、来源定位、断网播放、字体嵌入、图片许可和静态备份。
4. 检查10分钟讲稿的三轮彩排、交接、错数、应急删减和设备故障预案。
5. 检查5分钟答辩的主答、补充者和证据页码；未知问题不得现场编数字。
6. 保存提交文件、回执、版本、分工和人工核验记录。

## 自动预检边界

使用：

```bash
python3 scripts/validate_project.py path/to/report.md --meta path/to/project-meta.json
```

主预检脚本只识别Markdown/TXT中的最低模块、关键维度、字数、占位符、匿名泄露、地区、来源标记、PPT页数、查重状态和人工确认。DOCX另运行 `python3 scripts/validate_report_docx_format.py --strict-caption-coverage [--final-report] <file.docx>`；它检查文件结构、样式、题注和参考文献非表格，但仍不能证明事实真实、图片无泄漏、问卷有效、原创合规、字体实际渲染或评分质量。PDF/DOCX须用对应文件技能完整读取并逐页视觉检查。
