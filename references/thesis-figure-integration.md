# 学术图解润色与 `thesis-figure-skill` 路由

本协议把 `integrations/thesis-figure-skill/` 接入流通业经营分析报告。其上游来源为 `https://github.com/0xE1337/thesis-figure-skill`，MIT 许可。嵌入目录保留上游 `SKILL.md`、参考文件、验证器和示例骨架；主流程不得改写其内部规则，也不得把工具名称、代码、状态或生成过程写进参赛正文。

## 1. 能力边界

优先用于把已经核验的经营逻辑画成可编辑、可编译的学术图解：

- 研究框架、证据路径和章节关系；
- 企业价值链、商业模式、三流协同与渠道结构；
- 运营流程、顾客旅程、服务蓝图、责任泳道和阶段路线；
- 根因链、驱动树、瓶颈—方案—KPI映射与适用边界；
- 需要严谨连线、分区、层级或反馈关系的机制图。

量化统计图仍以经过验证的数据文件为唯一输入，先走 `$data-analytics:validate-data`，再走 `$data-analytics:visualize-data`。不得因为上游提供柱状、折线、热力等组件，就绕过数据门、复算、轴线和统计诊断。现场照片、企业年报原图和产品图片也不交给该工具“美化”到改变事实内容。

## 2. 启动条件

每张图建立图解契约后才调用嵌入 Skill：

1. 图号、章节和要支持的唯一判断；
2. 已确认的节点、关系、先后顺序和边界；
3. 每个事实节点的来源或团队判断标签；
4. 最终Word中的目标宽度、横竖比例和中文标签；
5. 不得出现的内容，包括院校、成员、内部证据ID、状态码和工具名。

如果原文只是一段没有结构关系的说明，保留为文字或表格；不得为了“每页有图”把段落机械装进方框。若节点关系尚未证实，图中须使用“待验证机制”而不是确定性箭头，正式交付前再消除内部占位状态。

## 3. 字号与可读性

Word中以最终嵌入尺寸为准，不以源文件画布为准：

- 图内普通中文标签最终不得小于11pt；
- 图例、坐标注释和必要脚注不得小于10.5pt；
- 关键数字、阶段名称和主节点宜为12—14pt；
- 优先输出SVG或PDF矢量图；不得放大低分辨率PNG；
- 同一图不超过9个主节点；超过时拆成总图与分图；
- 只保留1—2个视觉焦点，采用主报告配色，不套用与全文冲突的渐变主题。

生成后必须在最终DOCX渲染页的100%视图检查一次，在200%视图检查文字、箭头、边界、重叠和像素清晰度；再用灰度或黑白预览确认打印仍可辨。图的题注位于图下方并居中，来源注紧邻题注下方。

## 4. 生产步骤

1. 读取嵌入的 `SKILL.md` 全文，并只加载当前图型所需参考文件。
2. 先只读检测 `xelatex`、`pdftoppm`、draw.io CLI、Graphviz和Python依赖。上游“缺失小依赖自动pip安装”在本主Skill中改为**先报告并取得用户确认**；MacTeX、draw.io、Graphviz、Homebrew、系统字体和管理员权限均不得自动安装。
3. 遵守上游要求的布局草图、编译/渲染、重叠检测和视觉复核；上游要求使用多智能体审查时不得跳过。
4. 把最终可编辑源文件、矢量导出和预览PNG一起保存在项目工作目录；主Skill仓库只保存通用工具，不保存具体参赛企业的未公开材料。
5. 将图像以内联方式插入DOCX，设置替代文本，保持宽高比；用Word真实 `SEQ` 域生成图号。
6. 在最终页中复核图中所有文字是否可以直接阅读。无法在报告正常缩放下看清时，先删减或拆图，不把字号缩到门槛以下。

## 5. 禁止事项

- 不增添没有证据的数字、关系、节点、经营动作或预测结果；
- 不把统计相关性画成因果箭头；
- 不复制国一作品的成品构图、配色、图标或独特视觉；
- 不用图解替代问卷样本、访谈原话、财务底稿或模型诊断；
- 不在参赛正文出现 `TikZ`、`draw.io`、Skill、编译器、脚本路径或审查状态；
- 不以“美观”为由删除来源、样本、单位、期间、图例或不确定性说明。
