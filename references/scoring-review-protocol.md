## 1. 评分对象与状态

评分对象可以是：对话中已接受并组装的报告版本，或用户上传的 PDF、DOCX、Markdown 等完整报告。不得把讨论草稿、未接受章节和最终报告混在同一版本评分。

先记录两个独立状态：

### 评分状态

- `SCORABLE`：唯一终稿版本且文件从头到尾可读；报告自身缺少某个官方模块时仍可评分，并将该缺失作为报告缺陷。
- `PROVISIONAL`：大部分可读，但文件疑似上传不全、正文引用的独立附件未提供、章节尚未组装、关键图表不可读或版本冲突；可给较宽区间，必须低/中置信度。
- `UNSCORABLE`：只有提纲/摘要/截图片段，文件无法读取，或无法确认哪份是终稿；不给 60 分数字，只输出缺口诊断。

### 来源核验状态

- `REPORT_ONLY`：只看到报告；只能评价报告如何呈现证据，不能确认其中事实真实。
- `PARTIALLY_VERIFIED`：已检查部分关键底稿、原始数据或官方来源。
- `EVIDENCE_VERIFIED`：所有影响核心瓶颈和方案的关键主张均可追到已核验底稿；此状态少见，不得自行推定。

资格状态、评分状态和来源核验状态彼此独立。规则检查使用 `PASS / NOT_VERIFIED / RISK / BLOCK`，并注明它属于资格取消、固定扣分、评分项还是本技能的保守阶段门。发现资格阻断时仍可给“内容诊断分”，但必须标明不代表具备参赛资格。

## 2. 输入读取与版本锁定

### 对话产出的报告

1. 只纳入用户接受的章节批次和明确确认的修改；
2. 先组装一个带版本号的静态报告；未组装时最高为 `PROVISIONAL`；
3. 记录框架版本、章节批次、最后修改时间和未解决占位符；
4. 不用对话中被推翻的数字或旧标题补足终稿。

### 用户上传的报告

1. 记录绝对路径、文件类型、页数/字数、修改时间和版本名；多份文件先确认评分对象；
2. PDF 使用 PDF 技能：提取全文，检查目录、正文、图表、附录和参考资料；对扫描页、表格、图表、排版异常做视觉检查；
3. DOCX 使用文档技能读取并在需要时渲染，保留标题、表格、批注和页码关系；
4. 只收到截图或节选时设为 `UNSCORABLE` 或 `PROVISIONAL`，不得假设未提供部分存在；
5. 将“未定位到”写成未定位，不写成“报告不存在”，除非已检查完整全文和附录。

形成输入清单：报告版本、完整性、可读性、缺失附件、未解决占位符、是否能定位页码/章节、来源核验范围。

同时记录量表版本和校准状态：`RULE_BASED_ONLY / PARTIALLY_CALIBRATED / HUMAN_CALIBRATED`。当前只有规则与国一样本、没有人工逐项分数时，必须标 `RULE_BASED_ONLY`。

## 3. 证据标签和定位

评分证据使用四个标签：

| 标签 | 含义 | 能否直接支持加分 |
|---|---|---|
| `R` | 报告中可定位的陈述、图表、方法或附件 | 可以，但只能证明“报告这样呈现” |
| `V` | 已查看底稿、原始数据或权威来源并核验 | 可以，置信度高于 `R` |
| `I` | 评审者基于报告作出的推论 | 不能单独支持加分，必须说明推理 |
| `M` | 缺失、冲突、不可读、范围不符或无法验证 | 用于扣分、降置信度或触发上限 |

定位格式：

- PDF：`PDF物理页 p.12 / 印刷页 8 / §3.2 / 图3-1`；
- DOCX：`§3.2 / 表3-1 / 渲染页 p.12`；
- Markdown：`## 3.2 标题 / 段落首句`；
- 对话报告：`框架 v1.2 / 批次 B04 / §6.2`。

不得编造页码、表号、来源名、样本量或引文。网页链接存在不等于内容已核验；打不开时标 `M: source_not_checked`。

## 4. 评分流水线

严格按顺序执行：

```text
版本与可读性检查
  → 资格/匿名/格式风险（与60分分开）
  → 官方模块与五维覆盖
  → 逐维度证据矩阵
  → 第一遍独立评分
  → 第二遍反向审计
  → 区间、置信度与上限校准
  → 国一成熟度诊断（不加分）
  → 机器校验加总与定位字段
  → 输出修改优先级
```

每个官方维度必须先填：支持证据、反证/缺口、适用上限、分档理由；之后才能出现数字。先显示总分再补理由属于无效评分。

## 5. 双遍评分与分歧处理

### 第一遍：独立取证评分

按 [scoring-rubric-60.md](scoring-rubric-60.md) 逐维度评分。每次只看当前维度，先摘录定位证据，再给 `pass_a`；总分最后计算，避免整体印象污染单项。

### 第二遍：反向审计

不先查看第一遍数字，只审查：

- 报告声称与底稿是否混淆；
- 全国/集团口径是否冒充目标地区；
- 相关性是否被写成根因；
- 方法是否只有名称、没有执行；
- 结论是否新增信息或方案是否泛化；
- 图表、样本、年份、单位和引用是否冲突；
- 文字长度、排版、权威语气是否造成虚高。

完成扣分证据与上限判断后，再给 `pass_b`。

### 分歧处理

- 分析框架两遍相差不超过 2 分、其他维度不超过 1 分：可协调工作分，取两遍之间偏保守且符合证据的 0.5 分档。
- 超出上述阈值：不得简单平均；该维度标 `DISAGREEMENT`，区间覆盖两遍结果，置信度设 `LOW`，列明造成分歧的证据，并建议人工复核。
- 最终工作分必须位于区间内；总分和区间由各维度相加，禁止凭整体印象另调总分。

## 6. 区间与置信度

每个维度输出：`工作分 / 上限`、`合理区间`、`HIGH/MEDIUM/LOW`。

- `HIGH`：关键判断至少有明确定位，证据/底稿可复核，两遍评分在容差内，无重大矛盾。
- `MEDIUM`：报告定位充分，但部分底稿或外部来源未核验；两遍仍在容差内。
- `LOW`：报告不完整、关键图表不可读、核心证据只有推论、两遍分歧超阈值或存在重大口径冲突。

整体置信度规则：

- `REPORT_ONLY` 时总体最高为 `MEDIUM`；
- 任一关键维度为 `LOW`，总体不得为 `HIGH`；
- 两个及以上维度为 `LOW`，总体为 `LOW`；
- `PROVISIONAL` 的总体不得为 `HIGH`。

工作分是辅导用校准点，不是评委真实分数；优先呈现区间，不使用 52.37/60 之类伪精确数字。

## 7. 防幻觉硬规则

1. 只对可读取的确定版本评分；缺少内容不脑补。
2. 每项正向判断必须有 `R` 或 `V` 定位；`I` 不能独立加分。
3. 报告引用某来源不等于来源真实；未打开的来源标未核验。
4. 外部检索只用于核验，不得用网页内容替报告补写缺失章节再加分。
5. 不因报告更长、图更多、语言更像咨询报告而加分；重复和装饰性图表不加分。
6. 国一样本只提供结构诊断，不提供事实、分数锚点、页数目标、奖项概率或排名预测。
7. 无官方查重报告不得宣称“无抄袭”；只能说“本次未执行官方查重”。
8. 无原始问卷/访谈/观察记录不得宣称调研真实；只能评价报告是否提供了可复核说明。
9. 无地区损益、转化、复购、损耗等真实数据，不得将问卷态度或集团数据当作这些指标。
10. 修改建议不承诺“必涨几分”；标影响 `高/中/低`，修改后重新评分。
11. 不预测国一、晋级概率或具体名次；评分是训练性估计。
12. 不确定时缩小主张、扩大区间、降低置信度或转人工，不用流畅措辞掩盖未知。

## 8. 输出与复评

使用 [scoring-review-template.md](../assets/scoring-review-template.md) 输出，并同步生成基于 [scoring-scorecard-template.json](../assets/scoring-scorecard-template.json) 的工作计分卡。运行：

```bash
python3 scripts/validate_scorecard.py path/to/scorecard.json
```

校验通过后才交付数字。输出顺序：版本/状态 → 资格风险 → 证据覆盖 → 官方五维分数 → 总分区间 → 国一诊断 → 幻觉审计 → 高影响修改 → 复评条件。

复评时锁定旧版本和新版本，只重评受修改影响的维度，同时检查修改是否引入跨章冲突。展示“原区间 → 新区间”和证据变化；不得为了显示进步而自动抬分。

## 9. 人工校准与版本治理

11份国一作品只有获奖标签，没有组委会五维原始分数，不能用于反推出“国一分数线”，也不能验证本量表与真实评委的一致性。当前评分必须称为“规则锚定的辅导估计”。

若以后获得合法、匿名的人工逐项分数：

1. 由至少两名熟悉细则的人工评审独立评分，先不看 AI 分数；
2. 按五个官方维度比较 AI 工作分与人工中位数，记录绝对误差和系统性高估/低估；样本足够时再看等级相关性；
3. 单独分析争议案例，不因总分接近就忽略某维度持续偏差；
4. 只有覆盖多个业态、地区和质量档次的样本后，才可标 `HUMAN_CALIBRATED`；
5. 每次改变量表、上限或提示词都升级版本，并用同一匿名校准集回归测试；
6. 人工分数也不是事实真值，保留评审分歧和最终人工裁量。
