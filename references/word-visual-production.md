# Word美化、图表自动化与逐页视觉门禁

本协议用于把已接受的三批正文组装为可编辑 DOCX，并导出赛事要求的 A4 竖版 PDF。内容真实性优先于美化；图片和表格必须承担分析任务，不用于装饰或填空。

## 1. 能力路由

- **数据验证**：先调用 `$data-analytics:validate-data`，检查来源、样本、分母、期间、单位、计算、比较和因果措辞。
- **图表设计与制作**：调用 `$data-analytics:visualize-data`，为每张量化图建立“问题—结论—图形—数据—来源—最终载体”契约，导出可复现的 SVG 或高分辨率 PNG。
- **Word生成与检查**：调用 `$documents:documents`，使用其 Word 原生样式、表格几何、内联图片、图题表题、页眉页脚、隐私清理和 `render_docx.py` 逐页渲染流程。
- **Kami视觉参考**：读取 `integrations/kami/SKILL.md` 及任务所需的最少参考文件。嵌入版本为 1.12.0、MIT 许可、上游提交 `8bf6f46f74b5b640fa5612736a5cd24c724b7eca`。

Kami 原生生成 HTML/PDF，不原生生成 DOCX。因此，不能把 Kami 称为“Word生成器”：只迁移其编辑式层级、单一墨蓝强调、克制图解、留白和反 AI 套路原则；实际 DOCX 由文档技能制作并验证。比赛报告默认采用白色纸张的打印适配，不把 Kami 的暖色网页底铺满整页。嵌入版以本协议为上位流程，执行赛事Word任务时不运行 `check-update.sh`、`ensure-fonts.sh`、部署或HTML/PDF构建脚本；只有用户另行要求维护/生成Kami原生载体并完成依赖与网络审计后才可运行。

## 2. `cubec-a4-kami-print` 设计配置

官方只明确要求 A4 竖版 PDF，未规定字体、页边距或配色。以下是本 Skill 的工作默认；当届细则、学校模板或用户指定样式优先。

| 项目 | 工作默认 |
|---|---|
| 页面 | A4（210×297mm）竖版；上/下 24mm、左/右 25mm；装订或学校模板需要时使用命名覆盖 |
| 背景与颜色 | 白色页面；正文深灰黑；主强调 `#1B365D` 墨蓝；辅助浅暖灰 `#F5F4ED`；不使用渐变、3D和大面积彩底 |
| 字体 | 中文正文优先可用宋体/思源宋体，标题优先可用黑体/思源黑体；英文与数字使用同一可用西文字体；生成前检查本机字体，缺失时显式选择回退并重新渲染 |
| 正文 | 10.5—11pt、约1.3倍行距、段后适量留白；不靠缩到小字塞页 |
| 标题 | 使用 Word 的 Heading 1/2/3 真样式和真实多级编号；一级墨蓝，二三级保持克制层级 |
| 表格 | 只承载重复字段、比较、数据、进度或审计信息；固定宽度和列宽、首行重复、禁止固定行高截字 |
| 图片 | 默认内联，不用易漂移的浮动环绕；图片后紧跟图题、来源和必要口径；禁止拉伸低分辨率图片 |

所有数值均落实到 Word 样式和节属性，不依赖模板默认值。用户上传指定模板时，以模板为设计权威，不强行套用本配置。

## 3. 页眉页脚与匿名规则

- 封面可设置“首页不同”，不显示普通页眉；封面只能出现团队名称、作品名称和案例企业名称，以及有来源的案例视觉/信息表，不出现学校、成员、联系方式或校徽。
- 正文页眉左侧使用匿名作品短题名，右侧使用当前一级章节名；保持单行、低对比度，不放学校、团队成员、版本路径或“AI生成”等内部标签。
- 正文页脚使用真实页码字段，默认居中“第 X 页 / 共 Y 页”；目录页码必须在最终分页后更新。
- 组装后运行文档隐私清理，检查 creator、lastModifiedBy、自定义属性、修订会话 ID、批注、隐藏文本和图片元数据；文件名中的学校名称只按官方提交要求处理，不进入文档内容。

页码字段在无头渲染器中可能不自动刷新；需要时在 Word 更新全部域，或使用文档技能的字段物化工具，再重新渲染。

## 4. 图表自动化流水线

每张图/表先填写图表契约：

1. 对应章节、主张 ID 和要回答的分析问题；
2. 数据源 ID、原始文件/表、期间、地区、样本、指标、分母、单位和清洗规则；
3. 计划图形及为什么适合该比较；数据不足时的替代形式；
4. 标题、口径副标题、重点读数、邻接解释段和来源注；
5. 生成脚本/工作簿、导出文件、复算结果和最终 Word 图号；
6. 视觉检查：轴、零点、排序、标签、图例、色盲/灰度可辨和缩放后可读性。

先验证数据，再制图。趋势图通常需要足够连续观察点；只有少数离散期间时改用分组柱、斜率图、KPI表或精确表格。竞品对比使用同口径数据；问卷图标明有效样本和抽样边界；财务图保留公式、币种和合并范围。不得用双轴、3D、截断轴或花哨配色制造夸张结论。

每张图表只支持一个主要判断，正文紧邻一段“读数—比较—解释—含义—限制”。标题保持描述性，结论写在邻接正文，不让视觉标题超出数据能证明的范围。

## 5. 每页至少一图或一表

“每一页有图片或表格”按最终渲染页判断，不按 Word 编辑视图、章节计划或预计分页判断。每一页至少包含：

- 一张与本页主张直接相关、带图题和来源映射的图片（图表、地图、流程图、现场照片、产品/网点证据图等）；或
- 一张真正用于比较、查阅或审计的表格（经营数据、竞品对标、样本结构、证据矩阵、方案KPI、参考文献等）。

下列内容不计入覆盖：纯装饰图、无来源网络图、重复水印、Logo 单独占位、色块/文本框、把普通段落拆进单列表格、与邻近正文无关的图片。

先制作“页面—主张—图表”规划，再生成 DOCX；但分页会重排，所以规划不能替代最终检查。封面可用研究对象与证据范围信息表，目录页可用研究问题—章节—证据类型导航表；参考文献和附录页使用真实文献表、样本表或记录表，不加装饰图凑数。

## 6. Word生成与逐页复核

1. 锁定 `B01/B02/B03_ACCEPTED` 版本和证据台账，写第2章概要与第1章目录。
2. 建立 A4 设计令牌、页眉页脚、标题样式、编号、图题表题、交叉引用和可访问性规则。
3. 先完成图表契约和数据验证，再生成静态图；保留源数据与可复现脚本。
4. 生成 DOCX；使用真实表格几何、内联图片、重复表头、替代文本和相邻来源注。
5. 运行样式、图片、可访问性和隐私检查；更新目录、页码、图表编号与交叉引用。
6. 用 `$documents:documents` 的 `render_docx.py` 将 DOCX 渲染为每页 PNG，并可同时导出 PDF。
7. 逐页100%检查：图/表覆盖、清晰度、标题/来源邻接、截字、重叠、分页、字体、页眉页脚、匿名和目录页码。
8. 按真实渲染页填写 [word-visual-manifest-template.json](../assets/word-visual-manifest-template.json)，运行：

```bash
python3 scripts/validate_word_visual_manifest.py path/to/word-visual-manifest.json
```

9. 任一页缺少合格图/表时，优先移动或缩放相邻证据图、拆分有真实比较字段的表、调整段落/分页；不得添加无关装饰。任何调整都要重新渲染全部页面。
10. 只有脚本 `PASS` 且人工逐页检查通过，才能记录 `WORD_VISUAL_QA_PASSED` 并交付 DOCX/PDF。LibreOffice 不可用时必须说明“未完成逐页视觉门禁”，不得声称已确保每页覆盖。

## 7. 最终发布检查

- DOCX、PDF、目录、图题表题和参考文献使用同一报告版本；
- 每页至少一张合格图片或一张合格表格，且不是装饰性填充；
- 图表中的值能回到数据文件和证据 ID，关键计算已复算；
- 所有外部图片有合法来源/授权或为团队原创，现场照片完成隐私处理；
- 页眉页脚、文档属性、正文、图表和附录均无学校或个人信息；
- 未解决的 `[待团队核实]` 明确列出并阻断确定性结论或最终发布。
