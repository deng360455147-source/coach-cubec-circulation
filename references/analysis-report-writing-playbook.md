## 1. 开写条件

先读取调研阶段的“可写结论/暂不下结论/需补证”清单。只有“可写结论”能进入瓶颈和方案；“暂不下结论”可进入局限或后续验证；“需补证”必须返回调研。

开始正式正文前至少具备：

- 一句话中心命题和 2–4 个研究问题；
- 证据台账、样本/清洗说明和关键原始记录；
- 全国/集团、目标省市、样本点口径分层；
- 2–4 个候选瓶颈及支持证据与反证；
- 官方五维经营覆盖初步判断。

并非所有企业都会提供地区利润、订单转化或内部成本。缺失数据不一定阻断整份报告，但会阻断依赖它的结论：

| 缺失数据 | 可继续使用 | 不得声称 | 处理方式 |
|---|---|---|---|
| 地区利润/损益 | 集团财务承受力、门店观察、公开地区布局 | 本地区已亏损/盈利或精确利润改善 | 将财务结论降级为集团口径；方案做假设透明的情景测算 |
| 订单、转化、复购 | 问卷样本态度、访谈机制、现场运营代理 | 真实转化率、流失率或复购提升 | 把这些指标设为试点待测基线，不倒推结果 |
| 库存/损耗内部值 | 年报存货周转、可见缺货、员工访谈 | 某门店真实损耗或缺货率 | 只写外显现象和集团趋势；内部原因标待企业核实 |
| 概率样本 | 便利/配额样本内分组、定性机制 | 代表全市/全省的比例 | 明示样本结构和偏差，用竞品/观察/访谈交叉验证 |
| 企业管理者访谈 | 员工、商户、供应商、前员工和公开披露 | 管理层动机、组织冲突或决策细节 | 将内部根因改为机制假设或选择可外部验证的瓶颈 |

只要最终保留的核心瓶颈不依赖缺失数据，且已有合格交叉证据，可以带着透明局限进入正式写作；否则返回调研。

## 2. 强制框架确认门

报告阶段先按 [report-framework-and-section-writing.md](report-framework-and-section-writing.md) 进入 `FRAMEWORK_DRAFT`。使用 [report-framework-approval-template.md](../assets/report-framework-approval-template.md) 输出固定 11 章三级施工框架。官方“企业内部及外部分析”由“企业内部分析、企业外部分析、企业经营模式”三章共同满足；方案与实施依据国一样本高频功能独立成“经营优化方案”。

框架确认前只写：中心命题、精简的固定三级目录、每个三级标题下2—3行带状态概括、证据与精确定位、2—4项瓶颈及对应方案、缺口和篇幅建议；不得输出长篇正文。先运行 `python3 scripts/validate_report_framework.py <确认单.md>`；脚本为 `PASS` 且用户明确确认版本后，才记录 `FRAMEWORK_APPROVED`。若用户改变主问题、瓶颈/方案数量或跨章依赖，升级版本并重新确认受影响部分。

## 3. 写前五张工作底图

复制 [analysis-report-outline-template.md](../assets/analysis-report-outline-template.md)，完成：

1. **中心命题图**：地区变化、企业机制、经营矛盾、决策与指标；
2. **证据地图**：每个主张对应证据 ID、来源、口径、置信度、反证；
3. **章节论点图**：每章只有一个主结论，并说明输出到下一章什么；
4. **根因总链**：症状、量化差距、直接原因、结构性根因、可控性；
5. **瓶颈—方案矩阵**：根因、行动、责任、资源、KPI、风险和回滚一一对应。

任一核心瓶颈无法进入根因总链时，不要靠文字补齐，返回调研或删除。

## 4. 推荐报告框架

一级目录固定为11章；概要固定两个二级标题，引言使用“研究背景与选题价值、研究设计与范围”两个正式二级标题，并配置研究框架图；案例简介采用短结构和高密度年报数字画像；企业内部分析只保留战略、运营、财务三个二级标题。案例差异通过第8、9章的二级结果标题和各三级标题下2—3行概括体现。五个核心经营维度必须在固定主落点形成实质分析。

| 模块 | 核心任务 | 必须输出 |
|---|---|---|
| 1. 目录 | 准确导航固定结构 | 11 个一级章节、二三级标题与最终页码 |
| 2. 概要 | 最短篇幅给出全文答案 | 核心问题、主要发现和方案方向 |
| 3. 引言 | 凝练解释为什么研究、怎么研究 | 选题价值、研究问题、数据方法、范围与局限、研究框架图 |
| 4. 案例简介 | 只保留理解后文所需信息并提高数字证据密度 | 连续3—5年年报数据、企业业务/地区基础、两种READY模型的结果概览和案例价值 |
| 5. 企业内部分析 | 解释企业自身能力、约束和经营结果 | 企业战略、运营管理、财务状况 |
| 6. 企业外部分析 | 解释地区、行业、顾客与竞争如何传导 | 宏观地区、行业演进、市场竞争及外部机会 |
| 7. 企业经营模式 | 解释如何创造、交付和获取价值 | 商业模式、流通价值链、地区适配与扩张 |
| 8. 发展瓶颈 | 用2—4个通俗判断说清问题 | 每个二级标题直接写“问题+后果”，三级写表现、原因、影响 |
| 9. 经营优化方案 | 用对应办法解决每项瓶颈 | 每个二级标题直接写“改善结果+做法”，三级写动作、执行、验证 |
| 10. 结论与启示 | 回答问题并限定可迁移边界 | 结论、企业与地区启示、适用条件、局限 |
| 11. 附录及参考资料 | 保证企业数据、调研和引用可复核 | 企业重要数据、问卷、访谈纲要及知情/编码、参考文献、现场/竞品记录、补充图表与地区对标 |

固定通用三级标题承担施工功能。第8章保留2—4项瓶颈，第9章保留同等数量方案；两章二级标题必须直接概括结果，不得改回抽象分类。其余结构变化需升级框架版本并重新确认。

## 5. 框架和方法选择

先读 [report-section-method-router.md](report-section-method-router.md)。每个章节最多使用 1–2 个主方法；外部 skill 提供方法和检查项，不提供事实。无法满足最低数据条件时，删除、降级或将结论标为待验证。

| 要回答的问题 | 优先工具 | 最低数据条件 | 产出 |
|---|---|---|---|
| 地区布局/商圈/仓网是否错配 | GIS/POI、服务半径、网络节点或商圈比较 | 位置、覆盖、客群/订单或代理指标 | 空间差距与调整优先级 |
| 企业凭什么形成优势 | 价值链、VRIO、能力审计 | 资源、流程、结果及竞品对标 | 可持续/可复制能力判断 |
| 商业模式哪里创造或泄漏价值 | 商业模式画布、价值链、单位经济 | 客户、价值、渠道、收入、成本、伙伴 | 价值闭环与泄漏点 |
| 宏观变化如何影响经营 | PESTEL | 与企业动作/指标有因果联系的地区事实 | 机会/约束，不是政策清单 |
| 本地竞争压力来自哪里 | 本地竞品矩阵；必要时五力 | 同地区、同业态、同客群、同期间数据 | 差距、替代和竞争机制 |
| 顾客为何选择/放弃 | JTBD、分群、旅程、漏斗、问卷/访谈 | 最近行为、场景、替代、观察或交易证据 | 行为机制与细分差异 |
| 运营瓶颈位于哪里 | 流程图、约束分析、库存/排队/履约指标 | 流程节点、时间、成本、质量或异常 | 症状到直接原因 |
| 财务表现由什么驱动 | 趋势/结构/比率、单位经济、杜邦或情景 | 一致的期间、单位、业务范围与假设 | 驱动因素、承受力和方案边界 |
| 哪个原因最值得解决 | 因果树、5 Why、鱼骨、影响×可控性 | 多源证据、反证与企业约束 | 结构性根因与优先级 |
| 方案是否值得推广 | 逻辑模型、试点、前后/对照、敏感性 | 基线、KPI、时间、成本、停止条件 | 验证结论而非承诺效果 |

每个框架最多回答一个明确问题。无法提供所需数据时，删除或降级该框架，不画空洞模型图。

B01是例外的“双模型组合任务”：须读 [annual-report-empirical-methods.md](annual-report-empirical-methods.md)，对市场份额、协同效应、文化溢价DID和DEA‑Tobit逐一做可行性审查，只从READY中选两种。两种方法仍各自只回答一个问题；选择数量固定不代表可以降低识别和数据要求。

## 6. 章节与段落写法

### 6.1 结论式标题

标题表达判断及对象，例如：

- “核心商圈高覆盖未转化为年轻客群复购”优于“消费者分析”；
- “南部县域配送半径推高损耗并侵蚀单店盈亏”优于“物流问题”；
- “统一选品机制与本地需求分化形成 SKU 错配”优于“产品策略”。

### 6.2 分析段落六步

```text
结论：本段要证明什么
  → 证据：事实、指标、样本或案例
  → 对标：与时间、地区、竞品、目标或基线比较
  → 机制：为什么产生差距
  → 决策含义：对瓶颈或方案意味着什么
  → 边界：口径、反证、不确定性和不可外推范围
```

只有事实没有对标属于描述；只有相关关系没有机制不能写成根因；只有建议没有决策对象属于口号。

### 6.3 概要三段

1. 一句话交代企业、地区和核心问题；
2. 一小段概括最重要发现及2—4项瓶颈；
3. 一小段概括对应方案、验证方式和必要边界。

不单列大段背景、方法综述或企业历史；概要只复述正文已经证明的答案。

### 6.4 瓶颈与方案

瓶颈二级标题用普通读者能理解的一句话说清“什么问题造成什么后果”；方案二级标题说清“改善什么、采用什么做法”。不得只写“内部挑战、运营瓶颈、行动组合、实施路径”等空泛标题，也不得将竞争、政策或消费变化直接写成企业根因。

### 6.5 行业启示

先写可迁移机制，再写适用条件和不可复制条件。避免把单一企业经验上升为全国规律。行业启示应回答“哪些类型企业、在什么环境、具备什么资源时可以借鉴”。

## 7. 图表与证据配置

每张图表只支持一个判断，并在正文完成“读数—比较—解释—含义”。优先配置：

- 一张必备的研究框架和证据来源图，明确两种READY模型与后续经营诊断的连接；
- 一张企业业务/价值链或经营机制图；
- 一张全国—地区—样本点对比；
- 一组来自连续3—5年年报、口径一致的财务/经营趋势与结构图；
- 两种入选模型各至少一张结果或诊断图；
- 一张本地竞品矩阵；
- 每个核心瓶颈至少一张证据图；
- 一张瓶颈—方案映射和一张实施路线/KPI表。

图表下注明来源、期间、地区、业务范围、单位、样本量和必要口径。问卷图表同时注明有效样本、抽样方式和题目；访谈观点注明匿名角色和时间；计算图表保留公式与假设。

## 8. 固定对外交付顺序

对外交付固定为：

1. `B01`：引言 + 案例简介，确认后继续；
2. `B02`：企业内部分析 + 企业外部分析 + 企业经营模式，确认后继续；
3. `B03`：发展瓶颈 + 经营优化方案 + 结论与启示 + 附录及参考资料，确认后继续；
4. 三批均接受后，最后写概要、目录和题目并组装 Word/PDF。

内部准备仍先核对瓶颈卡、根因链、五个核心经营维度及其证据任务，以避免B01写成无关背景；但不得提前输出B02/B03正文或把未证明结论写入前文。B01先完成研究框架图、年报数据底稿、四类模型可行性审查、双模型Notebook和图表，再写解释文字。证据不足处保留 `[待团队核实：证据]`；少于两种READY模型时停止补数，不能用流畅语言或模拟结果隐藏缺口。

## 9. 分章节交付与复核

确认框架后，先读 [section-writing-evidence-protocol.md](section-writing-evidence-protocol.md)，再复制 [report-section-batch-template.md](../assets/report-section-batch-template.md)。严格按B01、B02、B03三批交付；每批先列施工说明，正文后做证据、口径、因果、结构、一致性和原创六项检查，并列出缺口及对后续章节的影响。未经用户接受当前批次，不自动推进下一批。

第4—7章必须先建立“主张—证据包”，综合专业文献、公开权威机构资料、权威网站、企业披露以及适配的竞品、消费者、产品和财务分析。不能打开原文或没有精确定位的资料不得标记为已核验。量化分析先调用 `$data-analytics:jupyter-notebooks` 形成可复现程序，再调用 `$data-analytics:validate-data` 复核结果，图表调用 `$data-analytics:visualize-data`。

从第一批起维护全局一致性台账：标准名称、时间与样本版本、核心数字、研究问题、瓶颈—根因—方案—KPI 唯一命名、图表/附录/引用编号和待核实项。修改已接受章节时同步检查所有下游章节。

## 10. 五轮审校

1. **事实轮**：来源、日期、期间、地区、单位、样本、计算和引用逐条核对；
2. **因果轮**：区分现象、相关、机制、根因和建议；查找反证与替代解释；
3. **结构轮**：每章输出是否进入下一章；重复背景、重复框架和企业百科删除；
4. **评分轮**：映射分析框架 20、对象 10、视角 10、方法 10、结论 10；
5. **交付轮**：匿名、原创、目录页码、图表编号、附录引用、文档属性和可读性。

## 11. 报告阶段门

只有同时满足以下条件才进入评分复核：

- 官方必含模块和五个经营维度均有实质分析；
- 地区性不是独立装饰章，而是进入经营机制与瓶颈；
- 2–4 个核心瓶颈均有交叉证据、根因、反证和优先级；
- 每项方案与根因一一对应，有责任、资源、KPI、试点和回滚；
- 概要、正文、结论、图表和附录的数字与口径一致；
- 没有复制国一样本，没有虚构内部数据和调研结果；
- 框架已有明确确认记录，所有章节批次已处理用户反馈并保持跨章一致；
- B01、B02、B03 均有明确版本和 `ACCEPTED` 记录；
- 若已生成 Word/PDF，最终渲染每页至少有一张合格图片或表格，页眉页脚、匿名和来源均通过 [word-visual-production.md](word-visual-production.md) 门禁；
- 团队已核验并进行实质性重写。
