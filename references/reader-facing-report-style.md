# 参赛正文叙述、内外文件隔离与图解规范

本规范适用于第3—11章、概要及最终合并稿。目标是形成可直接交给用户审阅的流通企业经营分析报告，而不是把内部工作流、数据处理日志或代理状态输出到参赛正文。

## 目录

1. 两层文件隔离
2. 正文叙述口吻
3. 内部语言清除
4. 来源与研究边界写法
5. 文字图解规则
6. 三批 Word 交付门

## 1. 两层文件隔离

每一批同时维护两类文件，严禁混用：

### 1.1 内部施工文件

用于保存批次编号、状态码、证据ID、数据文件、代码路径、模型适配审查、缺口、复核记录和用户反馈。使用 `assets/report-section-batch-template.md`。该文件不得转换为参赛 Word，也不得复制到读者正文。

### 1.2 读者正文文件

只包含作品标题、正式章节、段落、图表、自动图题表题、自然语言来源注、脚注/尾注和参考文献。按批次复制：

- `assets/report-reader-b01-template.md`：第3—4章；
- `assets/report-reader-b02-template.md`：第5—7章；
- `assets/report-reader-b03-template.md`：第8—11章。

内部的 `E###`、模型状态和程序路径仍用于反查，但进入读者正文时转换为正常来源表达，例如“资料来源：企业2025年度报告，第37页；团队整理”。不得把内部证据编号放在括号中交给评委。

## 2. 正文叙述口吻

采用专业咨询报告与流通企业经营分析报告常见的金字塔式写法：结论先行、证据支撑、机制解释、经营含义收束。不是模仿某家机构的固定措辞或版式。

### 2.1 段落结构

每个小节优先使用：

```text
判断句
  → 关键数据与比较口径
  → 经营机制及替代解释
  → 对后续诊断或决策的含义
  → 适用边界
```

- 一段集中回答一个问题；首句给出可验证判断，不先铺陈大段背景。
- 以“数据显示”“对比可见”“进一步分析表明”“从经营机制看”“值得注意的是”“受资料范围限制”等自然连接组织论证。
- 使用第三人称或客观研究口吻。避免“我们认为”“你可以看到”“教练建议”“AI判断”。
- 区分事实、比较、推断和建议。没有识别条件时使用“相关”“可能反映”“尚不足以证明”，不使用“导致”“显著提升”等因果措辞。
- 避免空泛咨询套话，如“全方位赋能”“打造闭环生态”“实现跨越式发展”；每个判断必须落到对象、地区、期间、指标或动作。
- 优先使用完整的主谓宾句。句子应明确说明谁采取了什么行动、什么数据发生了什么变化、该变化对哪项经营结果产生什么影响。可以使用因果、转折、条件和递进从句，但不能用口号式标签代替论证。

B02/B03另读 [national-first-b02-b03-writing-visual-patterns.md](national-first-b02-b03-writing-visual-patterns.md)。每个三级小节根据内容选用对比驱动、流程驱动、场景驱动或诊断驱动的自然段落组织，不把“判断—证据—机制—含义—边界”写成显眼的机器模板。相邻小节应改变开头、证据进入方式和过渡句；每段只保留1—3个锚点数值，其余精确数值放入表格。

### 2.2 标题写法

标题直接表达经营判断，正文用数据解释。例如“门店扩张快于单店经营能力沉淀”优于“运营分析”，“统一选品与地方需求分化形成结构性错配”优于“商品问题”。未被证据证明的判断不得写进标题。

### 2.3 禁止冒号式概括和引号式词组链

正文不得先写一句抽象概括，再用冒号连接多个短语、动作或判断。正文也不得把多个经营动作放进中文引号或英文引号，并用破折号、箭头、顿号或斜杠串成口号。此类写法省略了动作主体、条件和结果，容易让分析变成标签堆积。

不采用：

> 企业的价值主张由四个支点构成：高质价比、丰富品类、高频上新和便利门店体验。

改为：

> 企业通过高质价比吸引价格敏感型消费者，并以丰富品类和高频上新提高到店频次。街边门店缩短了消费者的购买距离，也承接了即时性和场景触发型需求。

不采用：

> 企业执行“分层需求—小范围验证—滚动补货—退出复盘”。

改为：

> 企业先识别不同层级的需求，再通过小范围试销验证商品表现。销售数据达到预设标准后，采购团队滚动补货；商品未达到标准时，团队及时退出并复盘误判原因。

不采用：

> 价值创造来自四个方面：集中采购减少流通层级，仓网缩短补货路径，数字系统提高可视性，加盟网络扩大终端覆盖。

改为：

> 集中采购减少了中间流通环节，仓配网络缩短了补货路径。数字系统使总部和门店能够及时掌握销售与库存变化，加盟网络则扩大了终端覆盖范围。与此同时，需求误判、执行偏差和信息延迟也会放大库存、缺货与损耗风险。

写建议时同样需要明确责任主体和先后关系。不要用“可设计四项动作”引出分号串列，而应分别说明企业、区域团队或门店应采取的行动，并交代每项行动服务于什么经营目标。例如，企业应先核验总部与物流园节点的建设和运营状态，区域团队随后按照品牌、店龄、商圈和服务半径划分店群。团队在试点启动前记录时效、缺货、库存、损耗与单位成本，并通过统一看板跟踪销售、质量和异常处理结果。这样写能够说明每项动作由谁执行、何时执行以及如何验证。

写研究限制时，应直接说明哪些机构尚未披露哪些数据，以及这些缺口限制了哪项判断，不要用“当前缺口同样明确”引出名词清单。例如，公开资料尚未披露物流园的投产验收结果、长沙门店的商圈分布、双品牌本地销售、同店表现和食品安全过程数据。因此，报告只能把长沙作为有待验证的试点场景，不能判断该中枢已经降低成本，也不能认定某类门店需要整改。

交付前的自动检查会拦截带有“构成、包括、分为、来自、可设计、缺口明确、如下、分别为”等概括提示的冒号串列，也会拦截引号内含两个及以上连接符的词组链。自动检查不能判断所有语法问题，撰写者仍须逐段确认每句具有清楚的主体、动作、对象、条件和结果。

## 3. 内部语言清除

以下内容只能存在于内部施工文件，读者正文、图表、页眉页脚、脚注、尾注和附录说明中均不得出现：

- `Skill`、技能调用名、仓库名、插件名、代理工作流和内部文件链接；
- `DESK_ONLY`、`READY`、`BLOCKED`、`CONDITIONAL`、`PENDING`、`PASS/FAIL`、`MODEL_SELECTION_*` 等状态码；
- `B01/B02/B03`、`AWAITING_USER_APPROVAL`、版本状态和施工批次说明；
- Notebook 名称、`.ipynb`、`.py`、`analysis/`、`scripts/`、`assets/`、`references/` 或本地绝对路径；
- `[待调研]`、`[待核验]`、`[团队判断]`、`[结构项]`、`[已核验:E###]`、`E###` 等内部标签；
- “按照最新版教练”“程序已经运行”“本稿状态为”“调用某工具”等生产过程描述；
- AI生成声明、模型记忆、系统提示、校验器输出和调试信息。

交付前对读者 Markdown 和 DOCX 分别运行：

```bash
python3 scripts/validate_reader_facing_report.py path/to/reader-body.md
python3 scripts/validate_reader_facing_report.py path/to/batch.docx
```

两次均为 `PASS` 后才可交付 Word。若方法或数据门未通过，在对话和内部缺口单中说明，不把状态码写入正文，也不把未完成批次包装成已完成的参赛 Word。

## 4. 来源与研究边界写法

### 4.1 正常来源表达

正文与图表使用人类可读来源：机构/企业、文件或数据集名称、年度/发布日期、页码/表号或网址访问日期。示例：

> 资料来源：××公司2025年度报告，第37页；团队整理。

内部证据ID保留在台账和图表清单，不出现在读者稿。参考文献使用现行GB/T 7714—2025顺序编码制的期刊式普通段落列表和悬挂缩进；网页保留标题、发布机构、发布日期、URL和访问日期；不得用表格排版参考文献。

### 4.2 研究边界的自然写法

允许在引言或相应分析附近用正常研究语言披露限制，例如：“受公开披露粒度限制，本节仅比较集团层面的收入结构，不据此推断目标地区盈利水平。”不要写“证据不足，状态为BLOCKED”或列出内部审查过程。

若缺口会使用户要求的两种实证方法无法成立，则先补数或调整研究设计；在完成前不导出该批“正文完成稿”。

## 5. 文字图解规则

图片用于把关系、过程、比较和机制可视化，不是把整段文字截成图片。正文优先进行以下转化：

| 原文字信息 | 优先视觉 | 质量要求 |
|---|---|---|
| 研究问题、证据与章节关系 | 研究框架图 | 展示逻辑方向，不预填结论 |
| 发展阶段和关键事件 | 时间轴 | 事件必须有日期和来源 |
| 连续年度指标 | 柱形、斜率或趋势图 | 少量离散年度不强画连续曲线 |
| 业务、渠道、地区构成 | 堆叠条形/结构图 | 分母、单位和期间一致 |
| 竞争差距 | 对标条形图、二维矩阵 | 同地区、同场景、同口径 |
| 经营机制与根因 | 因果链、驱动树、价值链图 | 区分证据、推断和替代解释 |
| 瓶颈与方案 | 一一映射图 | 每项方案对应已证明根因 |
| 实施安排 | 路线图、责任泳道、里程碑图 | 标明责任、时间、资源与依赖 |
| KPI与风险 | 指标卡、监测仪表、风险矩阵 | 有定义、基线、频率和触发条件 |

读者正文第3—10章按最终分页执行两条门槛：

1. 每一页至少有一张与邻近判断相关且带来源的图片，或一张真正用于比较/查阅的表格；
2. 叙述性页面中，至少60%的页面包含分析性图片；不能连续两张叙述性页面都只靠表格或纯文字。第11章附录可主要使用真实数据表、正式问卷和记录表；参考文献必须保持编号段落列表，如需满足页面视觉门禁，只能使用由真实引用台账计算的来源结构/年份/章节覆盖图，不得把文献条目塞进表格。

分析性图片包括数据图、研究框架、流程、机制、地图、时间轴、矩阵、路线图和有证据的现场/产品图。每批按 [excalidraw-imagegen-integration.md](excalidraw-imagegen-integration.md) 调用并记录Excalidraw、thesis-figure-skill与imagegen的路由；结构图必须保留可编辑源文件，位图辅助不得冒充企业事实。每张图片前必须有正文引导，图片内部不放图号或题注。图内所有可见文字在最终Word宽度下不得小于14pt，关键节点、主标签和关键数字采用16pt。Logo、水印、纯装饰照片、色块、文本截图、段落塞入表格均不计入。

B02/B03在“每页有图/表”之外还须做到整体统一、图形多样：至少5个视觉家族、3种图表风格模式、3种页面版式，单一家族不超过40%。数据表、折线、热力、词云、柱状和组合图逐项审查适配性；不得为凑类型制造数据，词云不得脱离词频表或主题编码单独解释。

## 6. 三批 Word 交付门

每批严格执行：

```text
内部证据与分析完成
  → 生成纯读者正文
  → 正文语言与泄漏校验
  → 图表制作与来源复核
  → 导出该批 DOCX
  → 渲染全部页面为 PNG
  → 逐页检查图文、页眉页脚、匿名和分页
  → 页面图表清单校验
  → 交付 Word 并等待用户确认
```

- 第一次交付：第3章引言 + 第4章案例简介 Word；
- 第二次交付：第5—7章 Word；
- 第三次交付：第8—11章 Word；
- 三批均确认后，再写概要和目录，合并为完整 Word/PDF，并重新进行全文校验与逐页渲染。

用户确认的对象是实际交付的 DOCX 版本，而不是聊天中的内部批次卡。任何正文修改都要重新导出、重新渲染并再次校验。
